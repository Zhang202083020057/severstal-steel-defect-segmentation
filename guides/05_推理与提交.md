# 05｜阈值、TTA 与提交

## 为什么需要阈值？

模型输出 0～1 概率，必须用阈值转换成 Mask。默认 0.5 不一定适合所有类别，尤其 Class 2 样本很少。

## 在验证集搜索四类阈值

以最终验证集最佳模型为例：

```bash
python tune_thresholds.py \
  --data-dir /root/autodl-tmp/kaggle/severstal-steel-defect-detection \
  --checkpoint /root/autodl-tmp/kaggle/outputs/FINAL_MODEL/best_model.pt \
  --output /root/autodl-tmp/kaggle/outputs/FINAL_MODEL/thresholds.json \
  --batch-size 4 \
  --num-workers 4
```

输出中的 `thresholds` 是四个类别各自的最佳候选值。阈值只能在验证集选择，不能根据隐藏测试答案选择。

## TTA 是什么？

水平翻转 TTA 的过程：

```text
原图 → 模型 → 概率A
翻转图 → 模型 → 概率B → 翻转回来
最终概率 = (A+B)/2
```

它通常让预测更稳定，但推理时间约增加一倍。必须比较有无 TTA 的验证或提交结果，不能默认它一定有效。

## 整体面积阈值与小连通区域过滤

冠军方案会在某类预测总像素太少时将整张 Mask 清空，并进一步删除小连通区域。脚本中：

- `--min-total-pixels`：该类整张 Mask 的最小总面积；
- `--min-sizes`：单个连通区域的最小面积。

冠军使用过总面积 `(600,600,900,2000)` 和小组件 150，但这是其模型上的参数，不能直接视为我们的最佳值。起步使用全 0，后续只在验证集验证有效后调整。

## 生成当前数据包格式的提交

假设阈值搜索得到 `0.45,0.55,0.5,0.5`：

```bash
python predict.py \
  --data-dir /root/autodl-tmp/kaggle/severstal-steel-defect-detection \
  --checkpoint /root/autodl-tmp/kaggle/outputs/FINAL_MODEL/best_model.pt \
  --output /root/autodl-tmp/kaggle/outputs/submission_compact.csv \
  --thresholds 0.45,0.55,0.5,0.5 \
  --min-total-pixels 0,0,0,0 \
  --min-sizes 0,0,0,0 \
  --tta hflip \
  --submission-format compact
```

本地 `sample_submission.csv` 是 compact 三列格式。但旧竞赛教程采用 original 两列格式。脚本也支持：

```bash
--submission-format original
```

真正跑全部测试图之前，先加 `--max-samples 8` 检查 CSV，再根据当前 Kaggle Late Submission 页面确认接受格式。

## Dice 再解释一次

```text
Dice = 2 × 预测与真实的交集 / (预测面积 + 真实面积)
```

本竞赛按每张图、每个类别计算，然后平均。真实与预测都为空时为 1；只有一方为空时为 0。因此误报空类别会被明显惩罚。

## 提交前检查

- 文件列名是否与当前样例一致；
- ImageId 是否全部来自 test_images；
- ClassId 是否有效；
- RLE 是否为正数、已排序且无重叠；
- 使用的 checkpoint、阈值和 TTA 是否记录；
- 不要把 smoke-test 模型误当正式模型提交。
