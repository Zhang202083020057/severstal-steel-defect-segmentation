# 00｜路线与模型选择

## 模型是不是需要自己选择？

需要，但“自己选择”不是随意挑一个模型，而是根据任务、时间、硬件和文书目标提出一条可验证的实验路线。

本项目采用下面的固定路线：

| 阶段 | 模型 | 编码器 | Loss | 增强 | TTA | 目的 |
|---|---|---|---|---|---|---|
| 工程冒烟 | 小样本 U-Net | ResNet34，无预训练 | BCE+Dice | 基础 | 无 | 证明代码能运行 |
| B0 基线 | U-Net | ImageNet ResNet34 | BCE+Dice | 基础 | 无 | 获得可比较起点 |
| A1 文书候选 | DeepLabV3+ | ImageNet ResNet34 | BCE+Dice | 基础 | 无 | 验证老师模板中的模型假设 |
| A2 高分方案候选 | FPN | ImageNet ResNet34 | BCE+Dice | 基础 | 无 | 验证竞赛前列常用框架 |
| O1 损失实验 | B0/A1/A2中最佳者 | 相同编码器 | Focal+Dice | 基础 | 无 | 单独验证 Focal Loss |
| O2 增强实验 | O1最佳设置 | 相同 | 相同 | 强增强 | 无 | 单独验证增强 |
| Final | 验证集最佳模型 | 相同 | 最优 | 最优 | 比较后决定 | 阈值与后处理后提交 |

## 为什么这样选？

1. **U-Net 是可靠基线**：结构简单，跳跃连接适合恢复缺陷边缘。
2. **固定 ResNet34 编码器**：竞赛第 4 名指出重型编码器与简单 ResNet34 表现接近；固定编码器也能更公平地比较解码框架。
3. **DeepLabV3+ 是候选而非预定赢家**：它的 ASPP 理论上适合多尺度缺陷，也符合老师模板，但本竞赛开源强方案报告 DeepLabV3 表现不佳，必须用本地验证决定是否采用。
4. **加入 FPN 候选**：第 1、3、4、10 名方案均大量采用 FPN，它比 DeepLabV3+更有本竞赛的经验依据。
5. **Focal Loss 有任务依据但不是结论**：第 3 名使用 Focal Loss，冠军则使用加权 BCE/BCE-Dice，说明损失函数也必须比较。
6. **增强与 TTA 都要验证**：前列方案的结论并不一致，有的使用翻转 TTA，有的认为收益很小；所以不能在训练前写成“有效策略”。

## 基线是什么意思？

基线不是“最差模型”，而是一个简单、稳定、可复现的参照物。后续声称“优化”必须和同一验证集上的基线比较。

## 公平对比原则

每轮实验尽量只修改一个主要变量，并保持以下条件一致：

- 相同训练/验证划分和随机种子；
- 相同输入尺寸；
- 相同训练轮数；
- 相同 Dice 实现；
- 相同测试集与提交格式。

如果同时换模型、Loss、增强、尺寸和训练轮数，即使分数提高，也无法判断究竟是哪一项有效。

## 你最终需要能口头解释

> 我先以 ResNet34-U-Net 建立可复现基线，并参考竞赛前列方案加入 FPN，同时将老师建议的 DeepLabV3+ 作为多尺度候选。在保持数据划分、输入尺寸和训练设置一致的前提下比较三种框架，再对最佳单模型分别评估 Focal Loss、数据增强、分类别阈值、面积后处理和水平翻转 TTA；最终模型由验证结果而不是预设结论决定。
