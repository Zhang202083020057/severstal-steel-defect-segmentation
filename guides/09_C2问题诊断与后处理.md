# C2 问题诊断与 V4 校准后处理说明

## 1. 目前 C2 到底出了什么问题

训练集中 C2 只有 247 张正样本图片，固定划分后训练集 198 张、验证集 49 张。V2、V3 在默认阈值 0.5 下都没有预测出任何 C2。

V4 进一步检查了模型输出概率。对 49 张 C2 验证正样本，C2 通道的全图最大概率中位数约为 `4.77e-7`，真实缺陷区域最大概率中位数为 `0`；负样本全图最大概率中位数同样约为 `4.77e-7`。把阈值降到 0.01 后，C2 正样本 Dice 和检出召回率仍为 0。

因此当前问题不是“阈值 0.5 太高”，而是模型把 C2 通道学成了几乎恒定的背景，正负样本没有形成有效区分。这称为输出通道塌缩。

## 2. V4 的校准后处理是怎么做的

模型对每个像素输出四个 logit，先经过 Sigmoid 转成 0～1 概率：

```text
probability = sigmoid(logit)
```

然后每个类别分别执行两步。

### 第一步：概率阈值二值化

```text
mask = probability > class_threshold
```

阈值较高时预测更保守，通常误报少、漏报多；阈值较低时预测更多，通常召回率提高，但可能增加噪声。

### 第二步：整张类别掩码的总面积过滤

```text
if mask.sum() < class_min_total_pixels:
    mask[:] = 0
```

例如某张图片的 C4 预测只有 500 个像素，而 C4 的最小总面积设为 800，那么这张图片的整张 C4 mask 会被清空。

这里使用的是 `min_total_pixels`：判断一张图片中某个类别的预测总面积。它不是连通域过滤，不会逐个删除小碎片；V4 的 `min_sizes` 仍然是 0。

### V4 实际参数

```text
thresholds       = 0.5,0.5,0.5,0.075
min_total_pixels = 0,0,800,800
min_sizes        = 0,0,0,0
TTA              = none
```

- C1：保持阈值 0.5，不做面积过滤；
- C2：保持阈值 0.5，不做面积过滤；降低阈值也无法产生有效预测；
- C3：阈值保持 0.5，过滤总面积小于 800 的预测，减少小面积误报；
- C4：阈值降到 0.075，提高召回率，再过滤总面积小于 800 的预测，抑制低阈值噪声。

对应推理命令：

```bash
python predict.py \
  --data-dir /kaggle/input/competitions/severstal-steel-defect-detection \
  --checkpoint best_model.pt \
  --output submission.csv \
  --thresholds 0.5,0.5,0.5,0.075 \
  --min-total-pixels 0,0,800,800 \
  --min-sizes 0,0,0,0 \
  --tta none \
  --submission-format original
```

## 3. 参数是怎么选出来的

V4 使用与训练时完全相同的固定验证集，不查看测试集标签。搜索：

- 14 个阈值：0.01～0.50；
- 8 个模型空间最小面积：0、5、10、25、50、100、200、400；
- 每个类别分别计算普通 Dice、正样本 Dice、图片级检出召回率、精确率和 F1。

模型输出分辨率为 256×800，测试提交前恢复到 256×1600，因此模型空间 400 像素近似换算为原图空间 800 像素。

验证集搜索得到 C3 为“阈值 0.5 + 模型空间面积 400”，C4 为“阈值 0.075 + 模型空间面积 400”。C1/C2 的普通 Dice 看起来很高，是因为绝大多数图片本来就是空 mask，而不是模型成功识别了缺陷。

V4 使 Kaggle Public / Private Dice 从 V2 的 `0.87369 / 0.86944` 提高到 `0.88093 / 0.87886`，但提升来自 C3/C4，并未改善 C2。

## 4. C2 可以怎么处理

### 优先级 1：先审计缩放是否破坏 C2 mask

原图是 256×1600，目前训练输入是 256×800，宽度缩小一半。C2 可能包含细、窄或面积很小的缺陷，缩放后可能只剩很少像素，甚至消失。

V5a 已完成以下不需要训练的检查：

- 比较每张 C2 mask 在 256×1600 和 256×800 下的像素数；
- 统计缩放后变为 0 像素或面积严重缩水的 C2 数量；
- 可视化若干原图、原始 mask 和缩放后 mask；
- 检查 RLE 解码和类别通道映射是否正确。

实际结果：247 张 C2 mask 缩放后没有任何一张完全消失；扣除宽度减半的预期面积变化后，像素保留率中位数为 1.000，最小值为 0.9367，只有 3 张图片出现连通区域减少。因此缩放不是当前 C2 通道完全塌缩的主要原因，下一步优先测试 Focal-Dice。完整结果见 [C2 标签与缩放审计](../experiments/C2_resolution_audit_2026-09-13/README.md)。

### 优先级 2：改变 Loss，让模型重视少数类正像素

普通 BCE 会被大量背景像素主导。建议以 V2 为对照，先只把 Loss 改成 `Focal + Dice`。Focal Loss 会降低大量容易背景像素的影响，把注意力放到难分类像素。

如果普通 Focal-Dice 仍然无法激活 C2，再尝试温和的分类别权重，例如提高 C2 通道权重；不能直接按 C3/C2 的约 20 倍设置，否则容易产生严重误报和过拟合。

### 优先级 3：缺陷区域 patch 训练

与整张长图缩放相比，围绕 C2 缺陷区域裁剪 patch 可以：

- 保留细小缺陷的像素细节；
- 提高一个训练样本中缺陷像素的比例；
- 让 Loss 更容易接收到 C2 正像素梯度。

训练时仍需混入正常区域和其他类别 patch，避免模型看到纹理就误判 C2。

### 优先级 4：采样只能作为辅助

V3 已经证明，单独把 C2 每轮期望抽样次数从 198 增加到约 715，并没有解决通道塌缩。后续若再使用采样，应与 Focal/类别加权 Loss 或缺陷 patch 配合，并控制重复次数。

### 更复杂的备选：分类器 + 分割器

可以先训练图片级分类器判断是否存在 C2，再仅对疑似 C2 图片运行分割或使用更低阈值。这可能改善“是否存在缺陷”的判断，但会增加系统复杂度，不建议作为下一步的第一个实验。

## 5. 推荐实验顺序

```text
V5a：C2 缩放与标签审计（不训练）
  ↓
V5b：V2 设置不变，只把 BCE+Dice 改成 Focal+Dice
  ↓
V6：若缩放损失明显，测试 256×1600 或 C2 缺陷 patch
  ↓
V7：在有效模型上重新做分类别阈值、面积过滤和可选 TTA
```

每个版本只改变一个主要因素，并继续记录 C2 正样本 Dice、检出召回率和预测非空数量。只有这些指标提高，才能写“改善了 C2 检测能力”。
